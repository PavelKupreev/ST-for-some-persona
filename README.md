# RPG-автосессия для SillyTavern

Расширение, в котором два героя из карточек ST играют сами, мастер-DM ведёт сюжет и бросает кубики 5e, а Историк пишет летопись. Требования: [TZ_ST-Autosession.md](TZ_ST-Autosession.md), план работ: [PLAN_ST-Autosession.md](PLAN_ST-Autosession.md).

Статус: этап 2 (ход по кнопке) завершён. Сцену можно играть по одному ходу на тестовых данных: мастер описывает, герои отвечают, кубики бросает код. Старта игры с генерацией мира и статов пока нет (этап 3).

## Установка

Рассчитано на последнюю стабильную SillyTavern (код сверялся с исходниками 1.19.0).

### Через «Install extension»
1. В ST откройте «Расширения» (значок кубиков) → «Install extension».
2. Вставьте ссылку `https://github.com/PavelKupreev/ST-for-some-persona` и нажмите «Install».
3. В правой колонке панели расширений появится блок «RPG-автосессия».

### Для разработки (без пуша на GitHub)
Подключите рабочую папку к ST ссылкой, тогда правки видны после обновления страницы (F5):

```bat
mklink /J "<папка ST>\data\default-user\extensions\ST-for-some-persona" "D:\Git on D\ST for some persona"
```

Команду выполнять в `cmd`. Если пользователь ST не `default-user`, подставьте свою папку из `data\`.

## Настройка OpenRouter

Расширение вызывает две модели: мастера (A, дороже, он же Историк) и героев (B, дешевле). Текущее подключение ST при этом не меняется.

Способ вызова выбирается в панели:

| Способ | Как работает | Где ключ |
|---|---|---|
| **Напрямую** (по умолчанию) | Браузер отправляет запрос прямо на `openrouter.ai` с нужной моделью. | В поле «Ключ OpenRouter» панели. Хранится в `settings.json` ST, в чат и его метаданные не попадает. |
| **Через сервер ST** (запасной) | Расширение отправляет запрос на `/api/backends/chat-completions/generate` с `chat_completion_source: openrouter` и нужной моделью, сервер ST подставляет ключ сам (`getContext().ChatCompletionService.processRequest`). | В «Подключениях API» ST, раздел Chat Completion → OpenRouter. Выбирать OpenRouter активным подключением не обязательно. |

### Результат спайка 1.2 (23.10.2026)

Оба способа вызывают две разные модели, не меняя текущее подключение ST. Основным выбран **прямой режим**: в живом ST он отработал без ошибок. Серверный режим на машине пользователя периодически падал с `self-signed certificate in certificate chain`. Скорее всего, HTTPS проверяет антивирус или VPN и подставляет свой сертификат: браузер ему доверяет, а Node.js сервера ST нет. Серверный режим оставлен в настройках как запасной. Его можно починить позже, например переменной `NODE_EXTRA_CA_CERTS` с сертификатом антивируса.

## Проверки этапа 1

| Кнопка | Что проверяет | Ожидаемый результат |
|---|---|---|
| 1.2 Тест моделей A и B | Вызов двух разных моделей | Две строки ✅ с ответами обеих моделей |
| 1.3 Счётчик в чате +1 | Запись в метаданные чата | После F5 и повторного открытия чата число то же |
| 1.4 Тест сообщений | Сообщения от «Мастера» и от карточки | Два сообщения с правильными именами и аватарами |

Лог промптов (галочка в панели): полный текст каждого запроса и ответа печатается в консоль браузера (F12 → Console), строки начинаются с `[RPG-автосессия]`.

## Проверки этапа 2: ход по кнопке

1. Откройте любой чат (лучше новый, сообщения игры добавляются в его конец).
2. Подготовьте мир и героев в блоке «Старт игры» (этап 3, ниже) и нажмите «Старт». Тестовые данные этапа 2 убраны: их заменил настоящий старт.
3. Включите «Лог промптов» и нажимайте «Один ход».

Одно нажатие — ход мастера, а затем ход героя, которого мастер выбрал меткой `[NEXT: hero1|hero2|master]`. Если мастер выбрал себя, нажатие заканчивается на нём. Если ход сорвался (ошибка API или неразбираемый ответ), очередь не сдвигается, и следующее нажатие повторит этот ход.

| Пункт | Что смотреть |
|---|---|
| 2.1 | В логе запрос `→ master`: блоки «МИР», «ГЕРОЙ 1/2» (статы, цели, микроцели, последние мысли), «ИСТОРИЯ СЦЕНЫ», «ЗАДАНИЕ» |
| 2.2 | В запросе `→ hero2` нет микроцели, целей и мыслей героя 1 |
| 2.3 | Ответ героя: метки `РЕПЛИКА / НАМЕРЕНИЕ / МЫСЛИ`, парсер понимает и жирный шрифт, заголовки, английские метки, JSON |
| 2.4 | Под репликой героя свёрнутый спойлер «💭 Мысли» |
| 2.5 | `node --test "tests/*.test.mjs"` — все тесты зелёные |
| 2.6 | Когда мастер ставит `[ROLL d20 DEX DC12 hero1]`: его текст, плашка «🎲 Имя, DEX: d20+2 = 15 vs DC 12 ✅», затем описание исхода |
| 2.7 | 5 нажатий подряд дают связную сцену |

«Сбросить сцену» очищает историю сцены в метаданных (сообщения в чате остаются), чтобы начать заново.

Промпты собираются из истории в метаданных чата, а не из сообщений чата. Поэтому мысли одного героя не попадают к другому, даже если в чате они видны спойлером.

## Проверки этапа 3: старт игры

Для первого теста в папке `test-cards/` лежат две карточки-примера: **Мира** (скромная девочка-маг, на русском) и **Grokk** (огромный тупой варвар, на английском, удобно для проверки языка игры). Импорт: список персонажей ST → «Import character from file» → выбрать оба `.json`.

Всё в блоке «Старт игры». Черновик (промпт мира, карточка мира, выбор карточек, листы героев, завязка) хранится в метаданных чата и переживает перезагрузку ST. Правки в полях сохраняются сами.

1. **Мир.** Напишите промпт мира, например «фэнтези, драконы», и нажмите «Расширить». Пока поле пустое, кнопка неактивна. Мастер вернёт карточку: сеттинг, 3–5 правил, эпоха, тон, уровень силы. Каждое поле можно править. Если мастер ответил не JSON, будет сообщение об ошибке, промпт останется в поле, «Расширить» можно нажать снова.
2. **Карточки.** Отметьте галочками ровно две карточки ST (есть поиск). Первая отмеченная станет героем 1. При 1 или 3 отмеченных «Сгенерировать» и «Старт» неактивны.
3. **Листы героев.** «Сгенерировать»: мастер по миру и карточкам выдаёт статы 1–20, HP, инвентарь, глобальную цель и тайную микроцель. Всё правится в форме, стат вне 1–20 подсвечивается и блокирует «Старт». Если мастер прислал битый JSON, будет сообщение: нажмите «Сгенерировать» ещё раз или «Заполнить вручную» (все статы 10, HP 10).
4. **Завязка.** Напишите завязку сцены или оставьте поле пустым, тогда мастер придумает её сам.
5. **Старт.** С этапа 4 кнопка «Старт» живёт в блоке «Автосессия» (см. ниже), подсказка под ней пишет, чего не хватает. Для ручной игры по одному ходу осталась кнопка «Один ход»: первое нажатие открывает сцену.

**Язык игры** (настройки вверху панели, по умолчанию «русский») подставляется во все промпты: мира, листов героев, мастера и героев. Проверка 3.5: возьмите карточку на английском, язык «русский», и реплики героев должны идти по-русски. И наоборот: язык «English» с русскими карточками.

| Пункт | Что смотреть |
|---|---|
| 3.1 | «фэнтези, драконы» → «Расширить» → карточка со всеми полями, любое поле редактируется |
| 3.2 | 1 или 3 карточки → «Старт» неактивен, 2 → активен (когда готовы мир и листы) |
| 3.3 | «Сгенерировать» → у каждого героя 6 статов 1–20, HP, глобальная цель, микроцель, всё редактируется |
| 3.4 | «Старт» с пустой завязкой и с заполненной: оба раза мастер открывает сцену (в логе `→ master` строка «Завязки нет: придумай её сам» или «Завязка от пользователя») |
| 3.5 | EN-карточка, язык «русский» → реплики на русском |

## Проверки этапа 4: автосессия

Блок «Автосессия» вверху панели: крупный счётчик оставшихся ходов, статус, кнопки и краткие листы героев (HP полоской, статы с модификаторами). Параметры — в «Настройках» → «Параметры автосессии».

**Что считается ходом.** Как в модели данных ТЗ, ход — реплика одного участника: мастера или одного героя. Ход мастера с броском (метка, плашка, описание исхода) считается одним ходом. Лимит N = 10 даёт примерно 5 реплик мастера и 5 реплик героев.

- **Старт** — новая сцена: очищает историю, восстанавливает HP, ставит счётчик на N и запускает ходы с задержкой между ними. Если в чате уже есть сцена, спросит подтверждение.
- **Пауза** — текущий ход доигрывается, новый не начинается.
- **Продолжить** — с того же места. Если лимит исчерпан, даёт ещё N ходов.
- **Стоп** — текущий ход доигрывается, сессия завершена. Дальше только новый «Старт» (или «Один ход» вручную).
- Остановки по лимиту, концу сцены и ошибке ставят сессию на паузу, пишут причину в панель, всплывающее уведомление и служебное сообщение в чат (скрыто от ИИ, в промпты не попадает).
- **Ошибка** (неверный ключ, сбой API, неразбираемый ответ) — пауза после первой же ошибки, без повторов. «Продолжить» повторяет именно сорвавшийся ход. Если сорвалось описание исхода после броска, кубики не перебрасываются.
- **Выбор следующего.** Сначала защита от молчания: герой, который молчит «порог» ходов подряд, ходит следующим (0 — выключено). После героя всегда ходит мастер. После мастера с вероятностью «случайность» его выбор заменяется случайным: герой 1, герой 2 или снова мастер. Каждое решение пишется в консоль (F12) строкой `следующий ход: ... — причина`.
- **Частота проверок** (0–100 %, по умолчанию 50). После каждого действия героя код бросает d100: если выпало не больше настройки, мастер обязан проверить действие броском d20, иначе бросков в этом ходе нет. 0 — игра без кубиков, 100 — проверка на каждое действие. Ход мастера не после героя (открытие сцены) идёт без бросков. В консоли строка `проверка действия hero1: нужна / нет`.
- **Мастер** пишет коротко (1–2 абзаца, до 100 слов): результат действий героев, реакция мира, глобальные события, речь NPC. Реплики героев он не пересказывает, а строки вида «Мира: ...» в его ответе вырезаются кодом.
- **Таймаут.** Задержка отсчитывается после ответа, поэтому ходы не накладываются, даже если модель думает дольше задержки. Если модель молчит 120 с, ход считается сорвавшимся: пауза с причиной «модель не ответила за 120 с».
- **Конец сцены.** Мастер ставит метку `[КОНЕЦ СЦЕНЫ]`. При включённом «Стоп в конце сцены» сессия встаёт на паузу с причиной «сцена завершена».
- После перезагрузки ST сессия, которая шла, показывается на паузе: «Продолжить» идёт с того же хода. Во время сессии не переключайте чат: ход в другой чат не запишется, сессия прервётся.

| Пункт | Что смотреть |
|---|---|
| 4.1 | «Старт» → ходы идут сами с задержкой. «Пауза» во время хода → ход дописывается, новых нет. «Продолжить» → с того же места. «Стоп» → «Продолжить» неактивна |
| 4.2 | Случайность 0 % → в консоли только «выбор мастера». 100 % → после каждого хода мастера «случайность 100 %» |
| 4.3 | Порог 4: если мастер зовёт одного героя, второй вступает, как только молчит 4 хода (в консоли «защита от молчания») |
| 4.4 | N = 10 → счётчик 10 → 0, при 0 пауза «лимит ходов исчерпан» |
| 4.5 | Переключатель включён, мастер ставит `[КОНЕЦ СЦЕНЫ]` → пауза «сцена завершена». Быстрее всего проверить запиской-завязкой «сцена короткая, заверши её через 2–3 хода» |
| 4.6 | Испортите ключ OpenRouter → «Старт» → пауза после первой ошибки, уведомление с причиной, повторных запросов нет. Верните ключ → «Продолжить» повторяет тот же ход |
| 4.7 | Счётчик, кнопки, HP и статы видны без прокрутки вниз и без полной страницы |
| 4.8 | Частота 0 % → ни одной плашки броска. 100 % → после каждой реплики героя плашка 🎲 |

## Тесты

Чистые модули (кубики, парсер, промпты, старт игры, очерёдность ходов) не зависят от ST и проверяются в Node 18+:

```bat
node --test "tests/*.test.mjs"
```

## Где что хранится

- Настройки расширения: `extensionSettings.rpgAutosession` (файл `settings.json` пользователя ST).
- Состояние игры: `chatMetadata.rpgAutosession` в файле конкретного чата. Ключи API туда не пишутся: перед сохранением поля `openrouterKey`, `apiKey`, `api_key` вычищаются.
